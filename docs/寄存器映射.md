# Modbus RTU 寄存器映射（调试接口 / 内部映射）

本机在 RS485 总线（uart8，9600 8N1）上作为 **Modbus RTU 从机**，从机地址由
`CONFIG_HOOK_MODBUS_SLAVE_ID` 配置（默认 1）。

> 上位机（云端）实际是通过 4G 模块的 MQTT / 0xA5 协议访问设备状态与下发指令，
> Modbus RTU 只用于工程调试，因此本表按"读写方向"重新划分并重新分配了地址
> （2026-09-17）：
>
> * **保持寄存器**（FC03 读 / FC06 写单个 / FC16 写多个）= 上位机/云端**写**的东西：
>   命令、配置、一次性 RTC 校准命令。
> * **输入寄存器**（FC04 读）= 上位机/云端**读**的东西：设备状态、BMS 遥测、当前时间。
>   固件只写不读（对外），云端无法误写状态值。
>
> 云端协议（0xA5）与寄存器地址解耦：`hook_cloud_proto.c` 按**名字**访问寄存器，
> 所以本次迁移不影响云端协议，只需要固件与调试脚本同步。

> 实现说明（问题点汇总 1 第 4 条）：寄存器表由 `module/modbus_data_model`
> 子模块承载（`app/hook_modbus/hook_register.c` 注册名称/地址/权限/默认值），
> Zephyr Modbus RTU 从机适配层直接读写该表。
> **未在表中定义的地址**：读回 0，写入被忽略（旧固件只是写进未使用的数组，
> 没有实际语义）。

## 保持寄存器 = 上位机 / 云端写入（FC03 / FC06 / FC16）

| 地址 | 名称 | 说明 |
| --- | --- | --- |
| 0x00 | `CMD_LED_SWITCH` | 爆闪灯闪烁开关：1 = 打开，0 = 关闭 |
| 0x01 | `CMD_BUZZER_7M` | 7 m 报警声触发：1 = 触发（3 m 优先） |
| 0x02 | `CMD_BUZZER_3M` | 3 m 报警声触发：1 = 触发 |
| 0x03 | `CMD_VOLUME` | 声光模块音量（0..31），变化后自动下发 |
| 0x04 | `CMD_HOST_HEARTBEAT` | **上位机心跳计数器**：上位机周期性写入，值变化即视为"上位机在线" |
| 0x10 | `POWER_ON_TIME` | 定时开机时间，北京时间：高字节时、低字节分（默认 0x0600 = 06:00）；**持久化** |
| 0x11 | `POWER_OFF_TIME` | 定时关机时间：高字节时、低字节分（默认 0x1500 = 21:00）；**持久化** |
| 0x12 | `STM32_STANDBY_ENABLE` | 硬待机使能：1 = 进入关机时段后进 STM32 STANDBY，由 RTC Alarm B 唤醒（独立于软待机） |
| 0x13 | `SOFT_STANDBY_ENABLE` | 软待机使能：1 = 处于关机时段时切断声光供电（默认 1） |
| 0x14 | `HEARTBEAT_ENABLE` | 心跳监督使能：1 = 启用（默认），0 = 不监督、供电常开 |
| 0x20 | `RTC_CAL_YEAR` | RTC 校准命令：年份（2000..2099，默认 0 = 未写入） |
| 0x21 | `RTC_CAL_MONTH_DAY` | RTC 校准命令：高字节月、低字节日（默认 0 = 未写入） |
| 0x22 | `RTC_CAL_HHMM` | RTC 校准命令：高字节时、低字节分（默认 0xFFFF = 未写入） |

## 输入寄存器 = 上位机 / 云端读取（FC04，对外只读）

固件用 `hook_reg_input_set()` 更新，FC04 没有写功能码，所以云端/上位机无法误写状态。

| 地址 | 名称 | 说明 |
| --- | --- | --- |
| 0x00 | `STATUS_WORK_MODE` | 工作模式：0 待机、1 正常、2 低电量、3 故障 |
| 0x01 | `REG_ERROR_CODE` | 系统错误码，见下表 |
| 0x02 | `STATUS_LED_SWITCH` | 灯光功能状态：1 = 正在"亮 2 s / 灭 1 s"闪烁（或报警声期间），0 = 已彻底关闭 |
| 0x03 | `STATUS_BUZZER` | 喇叭状态：0 = 关闭，1 = 7 m 报警，2 = 3 m 报警 |
| 0x04 | `STATUS_BMS_BATTERY` | BMS 电量；读取失败时为 0 |
| 0x05 | `STATUS_BMS_TOTAL_VOLTAGE` | BMS 总电压 |
| 0x06 | `STATUS_BMS_TOTAL_CURRENT` | BMS 总电流（取绝对值） |
| 0x07 | `STATUS_BMS_IS_CHARGE` | 0 放电、1 充电、2 静止 |
| 0x08 | `STATUS_BMS_REMAIN_DISCHARGE_TIME` | 剩余放电时间（分钟，20 次采样平均；无效为 0xFFFF） |
| 0x09 | `STATUS_BMS_REMAIN_CHARGE_TIME` | 剩余充电时间（分钟，20 次采样平均；无效为 0xFFFF） |
| 0x0A | `STATUS_BMS_PROTECT_STATUS` | BMS 保护状态寄存器（原样透传） |
| 0x10 | `INPUT_RTC_YEAR` | 当前北京时间年份（如 2026） |
| 0x11 | `INPUT_RTC_MONTH_DAY` | 当前北京时间：高字节月、低字节日 |
| 0x12 | `INPUT_RTC_TIME_HHMM` | 当前北京时间：高字节时、低字节分 |

其余地址保留（读 0）。

## RTC 校准流程（问题点汇总 1 第 3 条）

1. 上位机（Modbus RTU）或云端（0xA5 命令 0x09）写入校准值：
   `H0x20 = 年`、`H0x21 = (月 << 8) | 日`、`H0x22 = (时 << 8) | 分`（北京时间）。
   三个寄存器可以一条 FC16 帧一起写，也可以分三条 FC06 写。
2. `app/hook_rtc` 线程每秒检查一次，三个寄存器都离开“未写入”默认值且数值合法后：
   写入硬件 RTC（秒置 0）、调用 `rtc_trust_store_mark_valid(MANUAL)`、
   `time_source_rtc_refresh()` 重建 `time_manager` 信任记录，然后清空命令寄存器。
3. 只写了一半的命令 60 s 后自动丢弃并打印告警，避免半条命令被迟到补齐。
4. 校准前（trust 无效）定时关机、硬待机都不执行；校准后立即生效。
5. 秒不参与校准（本产品对时间精度要求不高）：校准值总是整分，之后由 RTC 走时。

## 定时开关机（问题点汇总 1 第 3.3 条）

* 关机窗口 = `[H0x11 关机, H0x10 开机)`（北京时间，跨零点自动处理：如 21:00 → 次 06:00）。
* 进入窗口且 `SOFT_STANDBY_ENABLE`(0x13) = 1：软待机 —— 清除灯光/声光命令、
  切断声光报警供电使能 `ALARM_POWER_EN`(PE5，原理图上是"警报灯供电使能")、
  熄灭 `PWD_LED`、暂停现场设备健康事件，工作模式变 0（待机）。
* 离开窗口：供电恢复、现场事件恢复、工作模式回到 1/2/3。
* 若 `STM32_STANDBY_ENABLE`(0x12) = 1：进入窗口后先做同样的输出关断，再按
  `POWER_ON_TIME` 设定 RTC Alarm B（按 UTC 编程）并进入 STM32 STANDBY，由 Alarm B
  唤醒；退出时开机的硬件状态由 `board_gpio_init()` 恢复。
  **硬待机与软待机互相独立**：只要 0x12 = 1 且 RTC 可信就会执行，不要求 0x13 = 1；
  0x13 只决定"不进硬待机时是否软待机"。
* 用**区间判断**而不是“精确到分钟触发”：设备若在关机时段内重启（比如 23:00
  断电恢复），会立即回到待机，而不是等到第二天 21:00（参考工程 `craner_ai_safety_car`
  用的是精确分钟触发，本工程更严格）。
* 前提：RTC trust 有效（H0x20/0x21/0x22 或云端校准过）。没有可信时间时只记录日志，
  不执行任何休眠动作。
* 0x10/0x11 会写入板载 W25Q64 QSPI Flash 的 `modbus-store` 分区（4 MiB 偏移
  0x20000，8 KiB）。W25Q64 的擦除单位是 4 KiB，store 的两个 bank 各自正好一个
  扇区，所以是**真正的双 bank**：保存过程中掉电只会退回上一份数据，不会丢配置。

```text
hook rtc                                   # 查看校准寄存器 / 显示寄存器 / trust / 内部 RTC
hook rtc set 2026-09-16 14:30              # 写校准寄存器（等价上位机写 H0x20..0x22）
hook reg 0x11 0x1500                       # 读/写保持寄存器（hook reg i0x12 读输入寄存器）
hook status                                # 工作模式、声光供电、定时、RTC、OTA 一览
modbus_data status                         # 持久化 store 状态（save_delay 3 s）
```

## 错误码（输入寄存器 0x01）

| 位 | 名称 | 含义 | 心跳灯表现 |
| --- | --- | --- | --- |
| 0x01 | `ERR_HEARTBEAT_TIMEOUT` | 上位机心跳丢失 > 60 s（声光供电已切断） | 每秒闪 1 次，间隔 2 s |
| 0x02 | `ERR_LED_OFFLINE` | 声光报警模块连续 3 次写超时（写超时约 1 s/次，≈4 s 内可判定） | 每秒闪 2 次，间隔 2 s |
| 0x04 | `ERR_BMS_READ_FAIL` | BMS 读取失败（**10 s** 内无成功读取；软待机期间同样检测） | 每秒闪 3 次，间隔 2 s |
| 多位同时置位 | — | 多重故障 | 快闪（爆闪） |

错误码为 0 时心跳灯为 1 s 亮 / 1 s 灭。

## 声光模块 LED 控制（最新固件行为）

模块内部的“慢闪”指令已不再使用，改由本机生成闪烁节拍：

| 步骤 | 时长 | 下发指令（写寄存器 0x00C2） |
| --- | --- | --- |
| 点亮 | 8 × 250 ms = 2 s | `0x0041` (`CMD_LED_ON`) |
| 熄灭 | 4 × 250 ms = 1 s | `0x0060` (`CMD_LED_OFF`) |

* 触发条件：`CMD_LED_SWITCH`(0) = 1 **或** `STATUS_BUZZER`(101) ≠ 0（报警声期间同步闪烁）。
* 板载 `PWD_LED`(PB3) 直接镜像 `CMD_LED_SWITCH`（上电默认低）。
* 声光报警的供电使能由 `ALARM_POWER_EN`(PE5，原理图"警报灯供电使能"，.ioc 里叫
  `FLASH_LIGHT_POWER_EN`) 单独控制，心跳超时切断供电不影响 `PWD_LED`。
* 每次步进变化或检测到 `ERR_LED_OFFLINE` 时才下发一次指令（避免总线刷屏）。

| 总线 | 外设 | 从机地址 | 说明 |

| RS485 | usart6 | 2 | BMS：电量、总电压/电流、保护状态、剩余充放电时间 |

## 云端二进制协议（4G 通道）

4G 模块（usr.cn 透传）在串口上以 `"<通道>,"` 前缀区分数据：

| 前缀 | 方向 | 含义 |
| --- | --- | --- |
| `1,` | 云端 → 本机 | 文本命令：`craner#AT...`（本机处理）或 `usr.cn#AT...`（转发给 4G 模块） |
| `2,` | 云端 → 本机 | 保留，忽略 |
| `3,` `4,` | 云端 → 本机 | 二进制 0xA5 帧 |
| `3,` | 本机 → 云端 | 二进制 0xA5 应答帧 |

帧格式：`0xA5 | SEQ | ID | LEN | DATA... | CRC16(低字节在前)`，
CRC 为 CRC16-CCITT（多项式 0x1021，初值 0x0000）。

命令 ID：0x01 灯光/声光控制、0x02 BMS 查询、0x04 心跳使能、0x05 工作心跳、
0x06 工作模式（只读）、0x07 软待机使能、0x08 定时开关机、0x09 当前时间、
0xF0 系统错误码。应答 ID 为命令 ID 加 0x80（`0x81`..`0x85`），错误应答在
数据段返回错误码（0x01 CRC、0x02 长度、0x03 未知 ID、0x04 不可读写）。

各命令数据段（与最新固件一致）：

| ID | 读应答 | 写请求 |
| --- | --- | --- |
| 0x01 灯光 | 1 字节：bit0 灯光功能、bit1 7 m 声、bit2 3 m 声、bit3..7 音量 | 1 字节同上（写）|
| 0x02 BMS | 12 字节小端：电量、总压、总流、剩余放电、剩余充电、保护状态 | 写请求返回 0x04 |
| 0x04 心跳使能 | 1 字节 | 1 字节 |
| 0x05 工作心跳 | 1 字节 | 写入不回应答 |
| 0x06 工作模式 | **2 字节**：`[mode, error_code]`，仅当 mode=3(DEVICE_ERROR) 时第 2 字节为错误码，否则为 0 | 只读，写请求返回 0x04 |
| 0x07 软待机使能 | 1 字节 | 1 字节 |
| 0x08 定时开关机 | 4 字节小端：开机、关机 | 4 字节同上 |
| 0x09 当前时间 | **6 字节**，3 个小端 `uint16`：年、`(月<<8)|日`、`(时<<8)|分` | 6 字节同上（写入即 RTC 校准请求；长度不符返回 `0x02`，数值越界返回 `0x04`） |
| 0xF0 系统错误码 | 1 字节错误码 | — |
