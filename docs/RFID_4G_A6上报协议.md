# RFID 4G A6上报协议（上位机对接版）

## 1. 接口概述

设备通过MQTT主动上报RFID采集结果。每个采集窗口内按UID去重；同一UID出现多次时，上报最后一次采集到的RSSI和状态标志。没有检测到标签时也会上报，`tag_count`为0。具体设备标识、上报周期和MQTT参数由产品配置决定，见文末产品参数表。

| 项目 | 值 |
| --- | --- |
| 传输方式 | MQTT二进制Payload |
| Topic格式 | `ai_safety/<device>/rfid/hook/server` |
| 应用层帧头 | `0xA6` |
| 协议版本 | `0x01` |
| 最大标签数 | 10 |
| 应用层ACK | 无 |

MQTT Payload是完整的A6二进制帧，从`0xA6`开始，到CRC16结束。文档中的空格和十六进制字符串仅用于展示，不会作为ASCII字符发送。

## 2. A6帧格式

```text
+--------+---------+----------+----------------+-----------+-------------+----------------+--------+
| Magic  | Version | Sequence | Payload Length | Tag Count | Frame Flags | Tag Records... | CRC16  |
| 1 byte | 1 byte  | 2 bytes  | 2 bytes        | 1 byte    | 1 byte      | N × 6 bytes    | 2 bytes|
+--------+---------+----------+----------------+-----------+-------------+----------------+--------+
```

| 偏移 | 长度 | 字段 | 字节序 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 1 | Magic | — | 固定为`0xA6` |
| 1 | 1 | Version | — | 当前固定为`0x01` |
| 2 | 2 | Sequence | 小端 | 本次启动内的发送序号 |
| 4 | 2 | Payload Length | 小端 | `2 + tag_count × 6` |
| 6 | 1 | Tag Count | — | 本帧标签数量，范围0～10 |
| 7 | 1 | Frame Flags | — | 帧级标志，V1固定为`0x00` |
| 8 | N×6 | Tag Records | 见下节 | 标签记录数组 |
| 8+N×6 | 2 | CRC16 | 小端 | CRC低字节先发送 |

A6帧总长度为：

```text
frame_length = 10 + tag_count × 6
```

固定部分为10字节，每条标签记录为6字节，因此合法A6帧的总长度始终为偶数。`Frame Flags`用于保持字节对齐并预留帧级扩展能力；V1发送端必须置0，接收端收到非0值时应判为当前版本不支持。

上位机必须同时校验：

```text
magic == 0xA6
version == 0x01
payload_length == 2 + tag_count × 6
received_frame_length == 6 + payload_length + 2
tag_count <= 10
frame_flags == 0x00
crc_received == crc_calculated
```

## 3. 标签记录格式

每条标签记录固定6字节，连续排列，不带子帧头或子长度。

| 相对偏移 | 长度 | 字段 | 字节序 | 说明 |
| ---: | ---: | --- | --- | --- |
| 0 | 4 | UID | 大端 | RFID标签4字节UID |
| 4 | 1 | RSSI | — | 标签信号强度，单位dB |
| 5 | 1 | Flags | — | 标签状态位，位定义见下表 |

Flags位定义：

| 位 | 名称 | 0 | 1 |
| ---: | --- | --- | --- |
| bit0 | Low Battery | 电量正常 | 低电量 |
| bit1～bit7 | Reserved | 固定为0 | 保留，当前不得发送1 |

设备侧根据RFID原始电量字节生成bit0：原始`0x21`（2.4～3.3V）转换为0；原始`0x18`（低于2.4V）转换为1。A6不上传原始电量字节、电压值或百分比。上位机必须使用按位判断：`low_battery = (flags & 0x01) != 0`。

例如标签数据：

```json
{"uid":"11025543","rssi":66,"low_battery":false}
```

对应的6字节记录为：

```text
11 02 55 43 42 00
```

其中`42`表示66dB，`00`表示Flags所有位为0，即电量正常。

V1协议不上传天线号、读卡器地址、RFID原始校验字节和采集时间。

## 4. CRC16

CRC参数与现有A5协议一致：

| 参数 | 值 |
| --- | --- |
| 算法 | CRC16-CCITT |
| 多项式 | `0x1021` |
| 初始值 | `0x0000` |
| 输入反转 | 否 |
| 输出反转 | 否 |
| 结果异或值 | `0x0000` |
| 计算范围 | 从Magic到最后一个标签数据字节，不包含CRC自身 |
| 发送顺序 | 小端，低字节在前 |

参考实现：

```c
uint16_t rfid_crc16_ccitt(const uint8_t *data, size_t length)
{
    uint16_t crc = 0x0000;

    for (size_t i = 0; i < length; ++i) {
        crc ^= (uint16_t)data[i] << 8;
        for (unsigned int bit = 0; bit < 8; ++bit) {
            crc = (crc & 0x8000) ?
                  (uint16_t)((crc << 1) ^ 0x1021) :
                  (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

## 5. 报文示例

### 5.1 没有检测到标签

序号为0、标签数量为0：

```text
A6 01 00 00 02 00 00 00 2B 53
```

| 字节 | 含义 |
| --- | --- |
| `A6` | 帧头 |
| `01` | 协议版本 |
| `00 00` | Sequence = 0 |
| `02 00` | Payload Length = 2 |
| `00` | Tag Count = 0 |
| `00` | Frame Flags = `0x00` |
| `2B 53` | CRC = `0x532B`，低字节在前 |

### 5.2 一个标签

序号为1，标签UID为`11025543`，RSSI=66dB，电量正常：

```text
A6 01 01 00 08 00 01 00 11 02 55 43 42 00 D2 77
```

| 字节 | 含义 |
| --- | --- |
| `A6` | 帧头 |
| `01` | 协议版本 |
| `01 00` | Sequence = 1 |
| `08 00` | Payload Length = 8 |
| `01` | Tag Count = 1 |
| `00` | Frame Flags = `0x00` |
| `11 02 55 43 42 00` | 一条标签记录，Flags=`0x00`表示电量正常 |
| `D2 77` | CRC = `0x77D2`，低字节在前 |

同一标签为低电量时，Flags改为`0x01`，完整报文为：

```text
A6 01 01 00 08 00 01 00 11 02 55 43 42 01 F3 67
```

## 6. Sequence规则

- MCU每次启动后从0开始；
- 完整A6帧成功进入4G发送队列后加1；
- 类型为无符号16位整数，到`65535`后回绕到0；
- 发送未被本地4G队列接受时，Sequence不增加；
- Sequence不是跨重启的全局唯一消息ID，上位机不能只依赖它永久去重。

## 7. 聚合和异常规则

1. 每个采集窗口内按4字节UID去重；
2. 同一UID重复出现时更新RSSI和Flags，保留最后一次状态；
3. 不同UID在同一A6帧中一次性上传；
4. 没有标签时仍发送`tag_count=0`的空窗口帧；
5. 单帧最多10个唯一UID，超过上限的新UID不会进入本帧；
6. 通信链路尚未就绪或本地发送失败时，当前集合不会清空；下一周期继续合并新标签并重试，因此异常恢复后的帧可能覆盖多个采集周期；
7. 当前没有应用层ACK，也没有Flash离线上报缓存；MQTT是否成功送达由MQTT链路的QoS机制负责。

空窗口只表示本周期没有采集到标签，不表示某张历史标签已经离线。若上位机需要标签在线/离线状态，应根据连续上报和业务超时时间自行维护。

## 8. 上位机推荐解析流程

```text
收到MQTT二进制Payload
        │
        ├─ 长度是否至少10字节
        ├─ Magic是否为A6
        ├─ Version是否支持
        ├─ 读取小端Payload Length、Tag Count和Frame Flags
        ├─ 校验长度关系及Tag Count上限
        ├─ 校验CRC16
        └─ 按6字节循环解析Tag Records
```

建议上位机保留原始Payload、设备Topic、接收时间和解析失败原因，方便现场排查长度、CRC或版本兼容问题。

## 9. 产品参数表

协议主体不绑定具体产品。当前已配置产品参数如下：

| 产品 | Device | MQTT Topic | 4G发布通道 | 上报周期 | QoS | Retain | 单帧最大标签数 | 空窗口上报 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: | --- |
| 产品10 | `ais504` | `ai_safety/ais504/rfid/hook/server` | 4 | 5秒 | 2 | 0 | 10 | 是，`tag_count=0` |

设备MCU内部使用`"4,"`选择4G发布通道，该前缀由4G模块消费，不属于MQTT Payload。上位机接收到的Payload始终从`0xA6`开始。
