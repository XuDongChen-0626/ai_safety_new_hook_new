# 健康监测、心跳灯与工作模式

本文记录当前实现：`module/system_health_service`（事件与动作）、
`app/hook_health`（产品事件定义、错误码、离线日志）、LED backend（心跳灯）和
`app/hook_work_mode`（工作模式聚合）。2026-10-27 起心跳灯不再由
`hook_supervisor` 自己驱动，`hook_supervisor` 已重命名为 `hook_work_mode`，
只保留工作模式聚合线程。

## 1. 健康事件

定义在 `app/hook_health/hook_health.c`：

| 事件 | 名称 | 离线超时 | 优先级 | 动作 | 错误码位 |
| --- | --- | --- | --- | --- | --- |
| `HOOK_HEALTH_EVENT_TASK_ALIVE` | `task_alive` | 12 s | 4 | LOG / SET_DEGRADED / STOP_WATCHDOG_FEED | — |
| `HOOK_HEALTH_EVENT_BMS` | `bms` | 10 s | 3 | LOG | `ERR_BMS_READ_FAIL` |
| `HOOK_HEALTH_EVENT_ALARM` | `alarm_module` | 15 s | 2 | LOG | `ERR_ALARM_OFFLINE` |
| `HOOK_HEALTH_EVENT_HOST_HEARTBEAT` | `host_heartbeat` | 60 s | 1 | LOG | `ERR_HEARTBEAT_TIMEOUT` |

- 优先级**只用于 LED**：数字 = 闪几下；多个事件同时离线时显示数字最小的那个；
  不参与动作掩码、超时、看门狗或复位策略。
- `task_alive` 超时由 IWDG 复位设备：
  `CONFIG_SYS_HEALTH_WATCHDOG_FEED_BACKEND=y`（30 s 超时、1 s 喂狗），
  该事件同时会置降级标志并显示 4 闪。
- 4G 模块没有独立健康事件：主机心跳事件已经覆盖 4G 下行链路。

## 2. 心跳灯（`heartbeat_led` / PD10）

由 `CONFIG_SYS_HEALTH_LED_INDICATOR_BACKEND=y` 驱动，跑在健康服务的 100 ms
周期回调里（没有独立线程）。

| 状态 | 灯语 |
| --- | --- |
| 正常（无离线事件） | 1 s 亮 / 1 s 灭 |
| 心跳离线（priority=1） | 闪 1 下，灭 2 s，循环 |
| 声光离线（priority=2） | 闪 2 下，灭 2 s，循环 |
| BMS 离线（priority=3） | 闪 3 下，灭 2 s，循环 |
| task_alive 超时（priority=4） | 闪 4 下，灭 2 s，循环 |

- 一次"闪"= 200 ms 亮 + 200 ms 灭（`SYS_HEALTH_ERROR_BLINK_MS=200`），
  一轮结束灭 2 s（`SYS_HEALTH_ERROR_PAUSE_MS=2000`）。
- **不做多错误快闪**：多个事件同时离线只显示优先级最高的一个。
- 开机自检关闭（`SYS_HEALTH_LED_SELF_TEST_MS=0`）。
- 现场命令：`health led status` / `health led on` / `health led off` /
  `health led auto`。

## 3. 错误码寄存器与"心跳超时切声光供电"

`REG_ERROR_CODE` 的三个位由健康事件回调维护，只有两处产品层覆盖：

1. 心跳超时（60 s）切声光供电：`hook_health_alarm_supply_lost()` 置
   `ERR_ALARM_OFFLINE` 并 **disable** `alarm_module` 事件（模块已断电，15 s 的
   "无应答"超时只会给出误导性的原因）。
   此时 LED 以**心跳**为原因显示：到达 60 s 时切断声光供电，同时
   `host_heartbeat` 健康事件进入离线状态并闪 1 下。
2. 进入软待机：清 `ERR_HEARTBEAT_TIMEOUT | ERR_ALARM_OFFLINE`，见下一节。

## 4. 软待机时的行为

`hook_rtc_sleep_enter()`：

- 关闭声光输出、切断 `ALARM_POWER_EN`、熄灭 PWD_LED；
- 清 `ERR_HEARTBEAT_TIMEOUT | ERR_ALARM_OFFLINE`；
- `hook_health_sleep_update(true)` → **disable** `alarm_module` 与
  `host_heartbeat` 两个健康事件（`sys_health_event_disable()` 会把离线状态清零，
  所以不会在待机中被重新判离线）；
- `bms` 事件**保持启用**（BMS 在待机期间仍然轮询，与原 CubeMX 固件一致）。

因此软待机期间：

- **心跳、声光不会报离线**，也不做断电动作、不统计心跳质量（`hook link` 不计数）；
- 心跳灯：无其他事件时显示**正常**；若 BMS 离线则闪 3 下；
- 声光报警器断电属于正常待机行为，不算"离线"。

`hook_rtc_sleep_leave()` 唤醒时重新 enable + report 两个事件，超时窗口从零开始：
声光 15 s、主机心跳 60 s；声光供电同时恢复。

## 5. 工作模式（输入寄存器 106）

`app/hook_work_mode` 的 `WorkModeTask`（100 ms）把错误码、电量、软待机标志聚合为
`STATUS_WORK_MODE`：

| 条件 | 模式值 |
| --- | --- |
| 有任意错误码 | `DEVICE_ERROR` = 3 |
| 软待机 | `MODE_DEVICE_STANDBY` = 0 |
| 电量 ≤ 低电阈值 | `MODE_LOW_BATTERY` = 2 |
| 其它 | `MODE_COM_WORKING` = 1 |

软待机状态由 `src/hook_system_state.c` 的原子状态 API 统一维护，RTC 调度逻辑是唯一写入方；
工作模式、心跳、声光模块和 shell 只读取状态快照。LED 不再参与这里的工作。

## 6. 现场检查

```text
health stats            # 每个事件的离线次数/当前离线时长/最长离线时长
health events           # 全部事件状态
health led status       # LED 后端状态（模式/自检/更新次数/引脚）
kernel thread list      # 确认没有 SysSupervisor，只有 WorkModeTask
hook link              # 主机心跳质量统计（待机期间不统计）
```

## 7. 已知取舍

- 多错误不做快闪，只显示优先级最高的原因；
- `task_alive` 超时由已启用的 IWDG 喂狗后端复位；
- 软待机期间不记录心跳/声光离线，避免夜间误报。

## 8. 日志级别与运行过滤

- `hook_bms`、`hook_alarm` 的底层轮询/写失败使用 `LOG_WRN_RATELIMIT`；
- `log_manage_app` 默认把 `modbus`、`hook_alarm`、`hook_bms`、
  `hook_health`、`system_health_service` 过滤到 `LOG_LEVEL_ERR`；
- 健康状态的离线转换使用 ERR，默认终端只保留当前离线状态；
- 在线恢复、底层通信失败和健康动作属于 WRN/INF，默认被过滤；
- 现场调试时可按日志源临时打开对应模块日志，定位后再恢复过滤。
