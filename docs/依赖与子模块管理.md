## 1. 为什么最初没有 `.gitmodules`（历史原因）

两个原因：

1. **重构当时本工程目录还不是一个 git 仓库**（`D:\CXD_WorkSpace\zephyrproject\projects\ai_safety_new_hook`
   下没有 `.git`）。没有父仓库，`.gitmodules` + gitlink 就无处登记。
2. 重构时目标目录为空、且构建环境**不能访问 GitHub**，无法执行
   `git submodule add https://github.com/HKCRC/xxx.git`。为了让工程能立刻离线编译，
   `module/*` 与 `tool/zephyr-dev-workflow` 是**从参考工程
   `craner_ai_safety_car` 复制的普通目录（vendored）**，而不是子模块。

参考工程 `craner_ai_safety_car` 是 git 仓库，因此它有 `.gitmodules` 管理这些子模块。

## 3. 方案 A：转换为真正的子模块（离线，保持与参考工程相同提交）

前提：本机有参考工程 `craner_ai_safety_car`（它的 `.git\modules\...` 里保留了各子模块的
完整 git 仓库）。全程不需要网络。

```powershell
$app = "D:\CXD_WorkSpace\zephyrproject\projects\ai_safety_new_hook"
$car = "D:\CXD_WorkSpace\zephyrproject\projects\craner_ai_safety_car"
Set-Location $app

# 1) 初始化本工程仓库
git init

# 2) 写入 .gitmodules（见第 5 节内容），然后：
git add .gitmodules

# 3) 逐个子模块：把参考工程的 git 仓库搬过来，并放置 gitlink 文件
$mods = @(
  "module\system_health_service",
  "module\time_manager_service",
  "module\ota_manager_service",
  "module\fault_dump_service",
  "tool\zephyr-dev-workflow"
)
foreach ($m in $mods) {
    $src = Join-Path $car ".git\modules\$m"      # 参考工程的子模块 git 目录
    $dst = Join-Path $app ".git\modules\$m"
    New-Item -ItemType Directory -Force -Path (Split-Path $dst) | Out-Null
    robocopy $src $dst /E /NFL /NDL /NJH /NJS | Out-Null
    $depth = ($m -split '\\').Count               # 目录层数，决定 ../ 的数量
    $rel = ("..\" * $depth) + ".git\modules\" + $m
    Set-Content -LiteralPath (Join-Path $app "$m\.git") -Value "gitdir: $rel"
}

# 4) 登记 gitlink（git 会把带 .git 的目录记为 submodule），并提交
git add -A
git commit -m "Adopt HKCRC modules as git submodules (same commits as craner_ai_safety_car)"

# 5) 校正子模块配置（URL/路径），检查状态
git submodule sync --recursive
git submodule status
```

完成后 `git submodule status` 应显示 5 个子模块及其提交号；新机器克隆时执行
`git submodule update --init --recursive` 即可从 GitHub 拉取相同版本。

## 4. 方案 B：从 GitHub 重新克隆（需要网络）

```powershell
Set-Location $app
git init
# 先把已有的模块目录移走（Git 不允许 submodule add 到非空目录）
Move-Item module\system_health_service module\system_health_service.bak
git submodule add https://github.com/HKCRC/system_health_service.git module/system_health_service
git -C module/system_health_service checkout 3af9bd02d8bcbc1dbff92c800047e4398d4603b1  # 固定到参考工程版本
# 其余 4 个同理
Remove-Item -Recurse module\system_health_service.bak
git add -A; git commit -m "Add HKCRC submodules"
```

> 注意：`git submodule add` 默认拉取上游**最新**提交，务必按上表 `checkout` 固定版本，
> 否则与当前已验证的构型不一致。

## 6. 转成子模块后的日常操作

| 场景 | 命令 |
| --- | --- |
| 新机器拉取 | `git clone --recurse-submodules <repo>` 或 `git submodule update --init --recursive` |
| 更新某模块到上游最新 | `git -C module/xxx fetch && git -C module/xxx checkout <sha> && git add module/xxx` |
| 查看当前各模块提交 | `git submodule status` |
| 编译（与现在一致） | `.\dev.ps1 build -target all -pristine`（模块仍在同一路径，CMake 无需改动） |

> 说明：CMake/Kconfig 是按**路径**引用这些目录的，转换成子模块后路径不变，
> 构建流程与现有 CI 不受影响。
