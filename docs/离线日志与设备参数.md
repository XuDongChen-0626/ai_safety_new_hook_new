# 离线日志、设备标识与 4G 质量统计

对应 `docs/问题点.md` 的「后续需要完善的功能点」第 **1、2、5** 条，实现方式与参考工程
`craner_ai_safety_car` 保持一致。

| # | 功能点 | 状态 | 主要文件 |
| --- | --- | --- | --- |
| 1 | 设备唯一标识 + 参数/工厂编号保存 | 已实现 | `module/device_identity_service`、`module/device_param_server`、`app/hook_params/`、`param-store` 分区 |
| 2 | 离线日志存 SD 卡 | 已实现 | `component/offline_log_service/`（原样移植 + 去网络依赖）、`&sdmmc1` + `fstab` |
| 5 | 4G 通信质量统计（心跳超时） | 已实现 | `app/hook_heartbeat/`（统计）、`hook link` / `craner#AT+LINK` 命令 |

构建影响：app `230,328 B` Flash（+60.5 KB）、`147,416 B` RAM（+22.3 KB），
MCUboot 不变（43,612 B）。

> 健康事件的超时、心跳灯灯语、软待机期间的暂停/恢复策略见
> [健康监测与指示灯.md](健康监测与指示灯.md)。

## 1. 设备标识与参数（功能点 1）

### 1.1 硬件身份（不需要保存）

`module/device_identity_service` 直接从 MCU 的 96 位 UID 派生，重启/换固件都不变：

| 字段 | 内容 | 用途 |
| --- | --- | --- |
| `hardware_uid` | UID 的十六进制串 | 唯一标识（云端映射用） |
| `short_id` | UID 哈希后的 4 位十六进制 | 话题/日志里的短标识 |
| `long_id` | 更长的派生标识 | 需要更长唯一串时使用 |
| `hostname` / `mdns_name` | `<company>-<model>-<product>` | 以太网产品用；本机无网络栈，仅作展示 |
| `mqtt_client_id` | `model[≤2] + short_id[4]`（6 字符） | 4G 模块的 MQTT Client ID（`AT+MQTTCID`） |

查看：`id show`（或 `device id`）。

### 1.2 可保存参数（QSPI Flash）

存储链路与参考工程相同：

```text
device_param_server ── Zephyr Settings ── ZMS ── QSPI param-store 分区
                                             (0x000000，128 KiB，W25Q64)
```

`zephyr,settings-partition = &param_store_partition;`（板级 dts），
`CONFIG_SETTINGS/ZMS/SETTINGS_ZMS/SETTINGS_ZMS_FORCE_MOUNT=y`。

| 参数 key | 来源 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `id.company` | identity 模块自动注册 | `craner`（`config/product_71.conf`） | 公司标签，改后**需重启**生效 |
| `id.model` | identity 模块自动注册 | `hook` | 型号，进 MQTT client id 前两位 |
| `id.product` | identity 模块自动注册 | 空 → 用 `short_id` | 产品标签 |
| `device.no` | `app/hook_params/` 注册 | 硬件 `short_id` | **工厂编号**（如 `998`），MQTT 话题用它拼 `ais998` |
| `mqtt.svr` | `app/hook_params/` 注册 | `mqtt.craner.hk` | MQTT 服务器（4G 自动配置下发） |
| `mqtt.port` | `app/hook_params/` 注册 | `1883` | MQTT 端口 |
| `mqtt.user` | `app/hook_params/` 注册 | `hkcrctest` | MQTT 用户名 |
| `mqtt.psw` | `app/hook_params/` 注册 | `crcHK3130` | MQTT 密码，日志/远端读取显示 `***` |
| `modem.cfg_hash` | `app/hook_4g_cfg/` 维护 | 空 | 已下发配置的指纹，变化即触发一次重配 |

出厂/现场写入流程：

```text
param list                       # 查看当前参数
param set device.no ais011       # 写工厂编号
param set id.model hook          # 需要时改型号/公司（重启生效）
param save                       # 落盘到 QSPI（必须执行）
param get device.no              # 回读确认
id show                          # 查看身份 + MQTT client id
```

代码侧读取：

```c
#include "hook_params.h"
const char *no  = hook_params_device_no();   /* "998"，默认是 short_id */
const char *tag = hook_params_device_tag();  /* 等于 device.no         */
```

`hook status` 与 `hook link` 都会打印 `device.no` 和 tag。「MQTT 话题自动组建」
（`app/hook_4g_cfg/`）用 `hook_params_device_no()` 拼 `ai_safety/ais<device.no>/...`，
细节见 [4G数据帧解析.md](4G数据帧解析.md) 第 4 节。

> 注意：`param set` 只改 RAM，必须 `param save` 才会写入 QSPI；`param factory_reset`
> 会清掉所有已保存参数（回到默认值）。

## 2. 离线日志（功能点 2）

### 2.1 硬件与挂载

* SD 卡座接 **SDMMC1：PC8(D0) / PC9(D1) / PC10(D2) / PC11(D3) / PC12(CK) / PD2(CMD)**，
  与参考工程同引脚；卡座无 CD 检测脚（插拔通过 `disk_access_status()` 的错误判断）。
* 本板把 PLL1Q 调到 48 MHz（960 MHz VCO / `div-q = <20>`），与参考工程一致，`clk-div = <2>`。
  Zephyr 的 STM32 SDMMC 驱动硬性要求 SDMMC 内核时钟正好 48 MHz，否则会拒绝初始化。
* FATFS 挂载点 `/SD:`（dts `fstab/sd_mp`），日志根目录 `/SD:/olog`。
* 卡必须是 **FAT32** 格式化过的（工程不自动格式化）。

### 2.2 文件布局

```text
/SD:/olog/pending/hook_pending_boot_000001.log                       # 还无可信时间
/SD:/olog/2026-09-18/hook_2026-09-18_09-12-33_000001.log            # 有可信时间后按天归档
```

每个文件头部三行记录上下文，便于脱离设备分析：

```text
# offline log v1 boot_ms=12345
# device product=ais011 model=hook host=craner-hook-ais011 uid=... short=1a2b
# fw app=1.0.0 board=craner_hook_stm32h743vit6
```

> `pending/` 里的文件在拿到可信时间（Modbus/云端校准 RTC）后会**迁移**到对应日期目录，
> 不会丢。

### 2.3 记录哪些事件

只记录「值得留痕的状态变化」，不镜像 Zephyr LOG 流（避免刷屏，和参考工程一致）：

| 分类 | 事件 |
| --- | --- |
| `system` | 启动（固件/板号/启动耗时）、设备身份、获得可信时间 |
| `power` | 进入/退出软待机、进入硬待机（STANDBY）、RTC 校准成功 |
| `4g` | 主机心跳超时（每次，含间隔与阈值）、心跳恢复、4G 接收缓冲溢出丢帧 |
| `bms` | BMS 离线 / 恢复（含离线时长） |
| `alarm` | 声光模块离线 / 恢复（含离线时长；主机心跳超时断电时直接判离线并暂停检测） |
| `ota` | OTA 接收器被武装、镜像写入 slot1 完成待重启、取消、失败、工程师确认 |
| `fault` | 复位原因（class/reason/conclusion）、上次致命故障记录（含线程/PC/LR）、OTA 回滚 |
| `param` | 参数列表（开机一次 + 每次 `param save` 真正写入后再记录一次） |

参数列表独立成 `param` 分类（不再混在 `system` 里），每行一条，带触发原因标签：

```text
[2026-09-18T09:12:33.123+08:00] <inf> [param] param device.no="ais011" (boot snapshot)
[2026-09-18T09:12:33.124+08:00] <inf> [param] param id.company="craner" (boot snapshot)
[2026-09-18T09:12:33.125+08:00] <inf> [param] param id.model="hook" (boot snapshot)
[2026-09-18T09:12:33.126+08:00] <inf> [param] param id.product="ais011" (boot snapshot)
[2026-09-18T09:20:02.421+08:00] <inf> [param] param device.no="ais012" (saved snapshot)
```

* `(boot snapshot)`：每次开机记录一次当前参数表（写在设备身份日志之后）。
* `(saved snapshot)`：只要 `param save` 真正写入过值（`device_param_server` 的 `save_count`
  增加）就再记录一次当前参数表；没有 dirty 项的空保存不会记录，避免刷日志。
* 记录范围 = 本工程参数表 + `id.company` / `id.model` / `id.product`
  （`module/device_identity_service` 注册的键，**取当前内存值**，所以从未保存过、仍是默认值的
  参数也会出现）+ Settings `param/` 子树里其它模块注册的已保存参数（未来新增的键会自动覆盖）。
* 设备标识本身不再单独写一条 `system` 记录：`device.no` 已由参数行给出，
  日志实际使用的 tag 规则（`device.no`，为空则回退 UID 派生的 `short_id`）见文件头的
  `host=` / `short=`，以及 `hook status` 的现场输出。
* 该功能只读参数与 Settings，不写 flash；保存动作本身仍由 `param save` 完成。

### 2.4 容量与保留策略（Kconfig 可调）

| 配置项 | 默认 | 含义 |
| --- | --- | --- |
| `OFFLINE_LOG_MAX_FILE_KB` | 1024 | 单个日志文件上限，超过则同一天内分卷 |
| `OFFLINE_LOG_RETENTION_DAYS` | 30 | 按天目录保留天数 |
| `OFFLINE_LOG_MAX_TOTAL_KB` | 32768 | 日志根目录总容量上限，超出按最旧目录清理 |
| `OFFLINE_LOG_PENDING_MAX_TOTAL_KB` | 同上 | 无可信时间时 `pending/` 的上限 |
| `OFFLINE_LOG_FREE_SPACE_MIN_KB` | 8192 | 保底剩余空间（不足则清理最旧目录） |
| `OFFLINE_LOG_QUEUE_SIZE` | 64 | 掉卡/写忙时的 RAM 队列深度（满则丢最旧） |
| `OFFLINE_LOG_MSG_MAX` | 192 | 单条事件正文长度上限 |

### 2.5 读取日志

三种方式，任选：

1. **拔卡**：FAT32，PC 直接打开 `olog/` 目录。
2. **本机 shell**：

   ```text
   olog status      # 卡是否挂载、当前文件、队列、剩余空间
   olog list        # 列出日志文件
   olog sync        # 把队列里的记录立刻刷到卡
   olog cleanup     # 手动执行保留策略清理
   olog rm <file>   # 删单个文件
   ```

3. **MCUmgr（SMP over shell / uart5）**：

   ```powershell
   mcumgr --conntype serial --connstring dev=COM7,baud=115200 fs list /SD:/olog
   mcumgr --conntype serial --connstring dev=COM7,baud=115200 fs download `
          /SD:/olog/2026-09-18/hook_2026-09-18_09-12-33_000001.log local.log
   mcumgr --conntype serial --connstring dev=COM7,baud=115200 fs status /SD:/olog/...
   ```

   只允许读/status/checksum `/SD:/olog` 下的文件，上传（写）与其它路径一律拒绝，
   且每次传输结束都会在日志里留一条 `mcumgr fs done ...`。
   注意：串口传输下 115200 baud 大约 4–6 KB/s，几百 KB 的日志需要 1–2 分钟。

### 2.6 现场验证

1. 插一张 FAT32 卡，上电看日志：`olog status` 应显示 `card_mounted=yes`；
2. `olog demo` 写一条各类别样例，`olog sync`，拔卡在 PC 上看文件；
3. 拔掉 4G 天线 / 断开上位机，观察 `4g` 分类是否出现心跳超时记录；
4. 触发一次 BMS 掉线（拔 RS485），看 `bms` 分类离线+恢复两条记录。

## 3. 4G 通信质量统计（功能点 5）

### 3.1 判据

上位机（主机）**稳定每秒写一次**心跳计数器（保持寄存器 `CMD_HOST_HEARTBEAT` 0x04）。
本工程统计的是**两次收到心跳之间的间隔**，用来反映下行（4G/MQTT → 设备）的稳定性：

* 间隔 > `CONFIG_HOOK_LINK_TIMEOUT_MS`（默认 **20000 ms = 20 s**）→ 记为**一次超时**，
  并在**心跳恢复的那一刻**写一条 `4g` 分类的离线日志；
* 与两个"产品动作"阈值区分开：`HEARTBEAT_SILENCE_MS`(10 s) = 清灯光/声光命令，
  `HEARTBEAT_TIMEOUT_MS`(60 s) = 切断声光供电 + 置 `ERR_HEARTBEAT_TIMEOUT`。

**一次离线只写一条日志**：超时是在"收到下一个心跳"时判定的（间隔超过 20 s），
不是每 20 s 写一次：

| 场景 | 记录 |
| --- | --- |
| 断链 40 s 后恢复 | **1 条**（gap 40 s），不是 2 条 |
| 断链 10 分钟 | 期间不写日志；`received` 停止增长、`host_heartbeat` 健康事件离线；恢复瞬间写 1 条 |
| 断链后再也没恢复 | 不再写新日志（不会刷满 SD 卡），离线状态由健康事件与心跳计数体现 |
| 软待机期间主机不发心跳 | **不统计、不记录**（软待机分支只喂时间戳，唤醒后第一个心跳 gap ≤ 1 个循环周期） |
| `HEARTBEAT_ENABLE=0`（上位机关闭监督） | 同样不统计 |

### 3.2 统计项

| 字段 | 含义 |
| --- | --- |
| `received` | 累计收到的心跳次数 |
| `timeouts` | 累计超时次数（间隔 > 阈值） |
| `interval_min_ms` / `interval_avg_ms` / `interval_max_ms` | 两次心跳间隔的最小/平均/最大值 |
| `timeout_max_ms` | 最长的一次超时间隔 |
| `last_timeout_ms` | 最近一次超时的**运行时间**（ms，0 = 从未） |
| `last_timeout_unix_s` | 最近一次超时的**墙上时间**（unix 秒，0 = 时间不可信） |

### 3.3 查看方式

**本机 shell**：

```text
hook link          # 显示统计（device tag、次数、间隔、最近一次超时时间）
hook link clear    # 清零重新统计
```

**云端（topic 1 的 AT 命令）**：链路质量是工程测量手段而不是上位机业务数据，
所以它和其他诊断命令一样放在 `craner#AT...` 通道，不占用 0xA5 协议：

```text
craner#AT+LINK        -> craner#+LINK:<received>,<timeouts>,<min>,<avg>,<max>,<longest timeout>   [ms]
craner#AT+LINK=clear  -> craner#OK        （清零重新统计）
```

**离线日志**：每次离线恢复写一行（含断链前最后一个心跳的时间戳），例如

```text
[2026-09-18T09:12:33.123+08:00] <wrn> [4g] host heartbeat timeout #3: no heartbeat for 40000 ms (threshold 20000 ms, previous beat unix 1758171153, recovered at uptime 812345 ms)
```

行首是恢复时刻的墙上时间，`previous beat unix` 是断链前最后一个心跳的时间戳，
一条记录即可算出这次离线的起止时间。

### 3.4 现场验证

1. 正常联网时 `hook link`：`interval min/avg/max` 应在 1000 ms 附近；
2. 拔 4G 天线几秒再插回：`timeouts` 增加，`hook link` 的 `last timeout` 显示墙上时间；
3. 云端发 `craner#AT+LINK` 核对字段；发 `craner#AT+LINK=clear` 确认统计清零（参数非法应回 `craner#ERROR`）；
4. 拔卡不影响功能（队列暂存），插回卡后 `olog sync` 可把未落盘记录写入。

## 4. 相关配置一览

| 配置 | 位置 | 说明 |
| --- | --- | --- |
| `CONFIG_DEVICE_IDENTITY_SERVICE` / `DEVICE_IDENTITY_USE_PARAM_SERVER` / `DEVICE_IDENTITY_SHELL` | prj.conf | 身份 + 使用参数服务 + shell |
| `CONFIG_DEVICE_PARAM_SERVER` / `_MAX_PARAMS` / `_MAX_VALUE_LEN` | prj.conf | 参数服务容量（32 项 / 64 B） |
| `CONFIG_SETTINGS` / `ZMS` / `SETTINGS_ZMS` / `_FORCE_MOUNT` | prj.conf | QSPI 持久化后端 |
| `CONFIG_DEVICE_IDENTITY_DEFAULT_COMPANY/MODEL/PRODUCT` | config/product_71.conf | 产品标签默认值 |
| `CONFIG_FILE_SYSTEM` / `DISK_ACCESS` / `DISK_DRIVER_SDMMC` / `FAT_FILESYSTEM_ELM` + FATFS 参数 | prj.conf | SD 卡 + FATFS |
| `CONFIG_OFFLINE_LOG_SERVICE` / `_SHELL` / `_MCUMGR` / `_WRITER_STACK_SIZE` / 各项容量 | prj.conf + component Kconfig | 离线日志 |
| `CONFIG_MCUMGR_GRP_FS*` | prj.conf | 通过 MCUmgr 拉取日志（SMP over shell） |
| `CONFIG_OFFLINE_LOG_FILE_PREFIX` | config/product_71.conf | 文件名前缀（默认 `hook`） |
| `CONFIG_HOOK_LINK_TIMEOUT_MS` | Kconfig（默认 20000，即 20 s） | 心跳超时统计阈值（一次离线只记一条） |

两个已知取值限制：

* `CONFIG_MCUMGR_GRP_FS_DL_CHUNK_SIZE` 未设置：SMP over shell 的净荷上限把它限制在 384 B，
  参考工程能设 1024 是因为它走以太网；
* `IWDG_STM32_INITIAL_TIMEOUT` 上限 26214 ms（Kconfig 按 LSI 最坏 40 kHz 估算），
  所以 30 s 只能由健康服务的 `CONFIG_SYS_HEALTH_WDT_TIMEOUT_MS` 提供（见 README 注意事项）。
