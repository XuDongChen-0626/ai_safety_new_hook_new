# 通过 4G/MQTT 远程修改参数与重配置 4G 模块

本文面向云端和上位机开发人员，说明如何通过 4G 模块的 MQTT 通道远程查询、修改、保存设备参数，并让设备在重启后自动重配置 4G 模块。

本文不使用现场 Shell。所有命令都由云端通过 MQTT 下发。

## 1. 适用范围

当前远程流程适用于产品 18 和产品 101：

- 产品 18 和产品 101 已启用 4G 模块；
- 产品 18 和产品 101 已启用开机自动重配置 `CONFIG_HOOK_4G_AUTO_RECONFIGURE`；
- 参数通过设备参数服务保存到 Settings/ZMS；
- 重启后，设备读取已保存参数并自动配置 4G 模块。

完整流程是：

```text
云端通过 MQTT 修改参数
        ↓
设备修改 RAM 参数
        ↓
云端发送 save，设备持久化到 Settings/ZMS
        ↓
云端发送 AT+SYSRESET
        ↓
MCU 重启并加载已保存参数
        ↓
开机自动 provisioning
        ↓
比较并写入 4G 模块配置
        ↓
4G 模块保存、重启并重新连接 MQTT
```

## 2. MQTT 通道

远程参数命令使用 MQTT 系统通道，即 4G 模块的订阅通道 1。

假设 `device.no=504`，云端向以下主题发送命令：

```text
ai_safety/ais504/system/server/hook
```

设备通过以下主题返回结果：

```text
ai_safety/ais504/system/hook/server
```

云端 MQTT Payload 直接填写 `craner#AT...` 命令，不需要在 Payload 前添加 `1,`。例如：

```text
craner#AT+PARAM=mqtt.svr
```

`1,` 是 4G 模块与 MCU 串口之间使用的内部话题编号，不属于云端 MQTT Payload。

## 3. 可远程修改的 4G 参数

| 参数 | 含义 | 产品 18 默认值 / 产品 101 默认值 | 影响 |
| --- | --- | --- | --- |
| `device.no` | 设备业务编号 | `504` / `503` | 决定 MQTT 主题中的 `ais<device.no>` |
| `mqtt.svr` | MQTT Broker 地址 | `mqtt.craner.hk` | 配置 4G 模块的 MQTT 服务器 |
| `mqtt.port` | MQTT Broker 端口 | `1883` | 配置服务器端口 |
| `mqtt.user` | MQTT 用户名 | `hkcrctest` | 配置 MQTT 登录用户名 |
| `mqtt.psw` | MQTT 密码 | `crcHK3130` | 配置 MQTT 登录密码 |

内部参数 `modem.cfg_hash` 用于记录已经应用到 4G 模块的配置指纹，由设备自动维护，云端不应修改。

MQTT Client ID 由设备自动生成：

```text
ais<device.no>-hook-<short_id>
```

例如 `device.no=504`、`short_id=95b6` 时，CID 为：

```text
ais504-hook-95b6
```

## 4. 远程参数命令

### 4.1 检查远程命令通道

云端发送：

```text
craner#AT
```

设备回复：

```text
craner#OK
```

收到回复说明 MQTT 系统通道、4G 串口和设备远程命令解析均正常。

### 4.2 查询全部参数

云端发送：

```text
craner#AT+PARAM
```

设备回复格式：

```text
craner#+PARAM:<数量>;device.no=<值>;mqtt.svr=<值>;mqtt.port=<值>;...
```

密码等敏感参数在远程查询结果中显示为：

```text
mqtt.psw=***
```

### 4.3 查询单个参数

```text
craner#AT+PARAM=device.no
```

示例回复：

```text
craner#+PARAM:device.no=504
```

查询 MQTT 服务器：

```text
craner#AT+PARAM=mqtt.svr
```

示例回复：

```text
craner#+PARAM:mqtt.svr=mqtt.craner.hk
```

### 4.4 修改参数但暂不保存

格式：

```text
craner#AT+PARAM=<key>,<value>
```

例如：

```text
craner#AT+PARAM=mqtt.svr,mqtt.example.com
```

成功回复：

```text
craner#OK
```

该操作只修改设备 RAM 中的当前值。断电或重启后，未保存的修改会丢失。

### 4.5 修改一个参数并立即保存

格式：

```text
craner#AT+PARAM=<key>,<value>,save
```

例如：

```text
craner#AT+PARAM=mqtt.port,1883,save
```

成功回复：

```text
craner#OK
```

该命令先修改 RAM 参数，再把所有 dirty 参数持久化到 Settings/ZMS。

### 4.6 一次修改多个参数后统一保存

依次发送：

```text
craner#AT+PARAM=mqtt.svr,mqtt.example.com
craner#AT+PARAM=mqtt.port,1883
craner#AT+PARAM=mqtt.user,example_user
craner#AT+PARAM=mqtt.psw,example_password
```

每条命令都收到 `craner#OK` 后，再发送：

```text
craner#AT+PARAM=save
```

这种方式只执行一次持久化写入，适合批量修改。

### 4.7 恢复单个参数默认值

```text
craner#AT+PARAM=reset,mqtt.svr
```

成功后还需要发送：

```text
craner#AT+PARAM=save
```

因为 `reset` 只恢复 RAM 当前值，不会自动持久化。

## 5. 保存参数与重配置的区别

远程参数操作涉及三份状态：

| 状态 | 存放位置 | 如何修改 |
| --- | --- | --- |
| 参数当前值 | MCU RAM | `AT+PARAM=<key>,<value>` |
| 参数持久化值 | MCU Settings/ZMS | `AT+PARAM=save` 或命令末尾加 `,save` |
| 4G 模块实际配置 | 4G 模块内部 Flash | MCU 重启后的自动 provisioning |

收到参数保存成功回复，不表示 4G 模块已经切换到新服务器、账号或主题。

当前没有提供远程 `hook provision run` 命令。通过 4G 远程修改参数后的正式生效流程是：

1. 保存参数；
2. 发送远程系统重启命令；
3. 产品 18 或产品 101 开机自动 provisioning；
4. provisioning 把已保存参数配置到 4G 模块。

## 6. 远程触发 4G 重配置

### 6.1 重启前确认参数

保存后重新查询非密码参数：

```text
craner#AT+PARAM=device.no
craner#AT+PARAM=mqtt.svr
craner#AT+PARAM=mqtt.port
craner#AT+PARAM=mqtt.user
```

密码远程查询只会返回 `***`，应以设置密码时收到的 `craner#OK` 作为成功依据。

### 6.2 发送系统重启命令

云端发送：

```text
craner#AT+SYSRESET
```

当前实现收到该命令约 200 ms 后直接重启 MCU，不发送确认回复。因此云端不应等待 `craner#OK`，应把 MQTT 断线和随后重新上线作为重启结果。

### 6.3 开机自动重配置过程

产品 18 或产品 101 重启后会：

1. 从 Settings/ZMS 加载已保存的 `device.no` 和 `mqtt.*` 参数；
2. 等待 4G 模块启动；
3. 读取 4G 模块现有工作模式和 MQTT 配置；
4. 计算当前期望配置指纹；
5. 配置指纹或实际配置不一致时，重新写入 4G 模块；
6. 发送 `AT+S` 保存 4G 模块配置并让模块重启；
7. 读回配置并校验 MQTT 连接；
8. 配置完成后进入 `done` 状态，RFID 等业务上报开始发送。

如果服务器、账号、密码、设备编号或固件定义的话题发生变化，配置指纹会变化，自动流程会执行完整重配置。

## 7. 完整操作示例

### 7.1 只修改 MQTT 服务器

```text
craner#AT
craner#AT+PARAM=mqtt.svr,mqtt.example.com,save
craner#AT+PARAM=mqtt.svr
craner#AT+SYSRESET
```

预期过程：

1. 前三条命令收到对应回复；
2. `AT+SYSRESET` 不回复；
3. 当前 MQTT 连接断开；
4. 设备重启并自动配置 4G 模块；
5. 设备连接到新的 MQTT 服务器。

### 7.2 批量修改服务器、账号和密码

```text
craner#AT+PARAM=mqtt.svr,mqtt.example.com
craner#AT+PARAM=mqtt.port,1883
craner#AT+PARAM=mqtt.user,example_user
craner#AT+PARAM=mqtt.psw,example_password
craner#AT+PARAM=save
craner#AT+PARAM=mqtt.svr
craner#AT+PARAM=mqtt.port
craner#AT+PARAM=mqtt.user
craner#AT+SYSRESET
```

必须在收到 `AT+PARAM=save` 的 `craner#OK` 后，才能发送 `AT+SYSRESET`。

### 7.3 修改设备编号

假设当前设备编号为 `504`，准备修改为 `510`：

```text
craner#AT+PARAM=device.no,510,save
craner#AT+PARAM=device.no
craner#AT+SYSRESET
```

重启前使用的主题是：

```text
ai_safety/ais504/system/server/hook
ai_safety/ais504/system/hook/server
```

重配置后改为：

```text
ai_safety/ais510/system/server/hook
ai_safety/ais510/system/hook/server
```

如果硬件 `short_id=95b6`，新的 CID 为：

```text
ais510-hook-95b6
```

云端必须在触发重启前准备好新设备编号对应的主题订阅和权限，否则设备重连后，云端会在旧主题上看不到它。

## 8. 修改连接参数时的注意事项

### 8.1 修改 `device.no`

`device.no` 会改变全部 MQTT 发布主题、订阅主题以及 CID 中的设备编号部分。云端应先创建新主题权限和订阅，再触发设备重启。

### 8.2 修改 MQTT 服务器

设备重启后会离开旧 Broker，并连接新 Broker。应提前确认：

- 新服务器可以从设备 SIM 卡网络访问；
- 端口已经开放；
- 用户名和密码有效；
- 新服务器已配置所需主题权限。

旧 Broker 无法获知设备在新 Broker 上的连接结果。

### 8.3 修改密码

密码不能远程读回明文。建议设置密码并收到 `craner#OK` 后，确认保存成功，再触发重启。

### 8.4 不要先重启再保存

错误流程：

```text
craner#AT+PARAM=mqtt.svr,mqtt.example.com
craner#AT+SYSRESET
```

因为第一个命令只修改 RAM，重启后修改会丢失。

正确流程：

```text
craner#AT+PARAM=mqtt.svr,mqtt.example.com
craner#AT+PARAM=save
craner#AT+SYSRESET
```

## 9. 回复和错误格式

成功修改或保存：

```text
craner#OK
```

参数错误回复：

```text
craner#+PARAMERR:<reason>
```

| 回复 | 含义 |
| --- | --- |
| `craner#+PARAMERR:argument` | 参数格式或长度错误 |
| `craner#+PARAMERR:key` | 参数名为空或不存在 |
| `craner#+PARAMERR:set` | 参数写入失败 |
| `craner#+PARAMERR:save` | Settings/ZMS 持久化失败 |
| `craner#+PARAMERR:reset` | 恢复默认值失败 |

云端应为每条需要回复的命令设置超时，只有收到对应成功回复后才继续下一步。`AT+SYSRESET` 是例外：当前实现不会回复。

## 10. 当前限制

- 远程 `AT+PARAM` 查询的是 RAM 当前值，没有单独查询 Flash 值的命令；
- 远程回复不包含 `dirty` 状态；
- 没有远程直接执行 provisioning 的命令；
- provisioning 状态没有通过远程命令返回；
- `AT+SYSRESET` 当前不发送确认回复；
- 修改为错误的 Broker、账号、密码或主题权限后，设备可能无法再次通过 MQTT 远程修正，只能现场处理。

因此，远程修改连接参数应由云端按顺序执行、逐条确认，并保留现场恢复手段。
