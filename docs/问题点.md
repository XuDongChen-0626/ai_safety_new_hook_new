1. 当前项目需要添加device_identity_service子模块，用于管理设备的唯一标识，同时还需要保存并管理设备的唯一标识，device_param_server子模块可以实现这个功能吗？若能实现，帮我我把device_param_server子模块也添加到项目中
2. 当前项目需要添加离线日志的功能，记录设备的运行状态、事件、异常信息等，并存储在SD卡中，暂不考虑如何将日志上传服务器中（这部分可以参考craner_ai_safety_car项目的实现）
3. 当前项目需要完善MQTT话题的组建，通过设备的唯一标识去组建该设备的MQTT话题，并由程序去自主设置4G模块的MQTT话题、模式等，而不再需要工程师手动通过终端去设置，简化出产设置流程。
4. 实测当前项目的MQTT+OTA固件更新方案，有以下几个弊端：
    1. 固件下载太慢
    2. 固件更新过程中，不能有其余话题数据出现，否则固件更新会失败
因此，我想测试一下http+OTA固件更新方案，看是否能更好的实现设备的固件更新。该4G模块有http模式，可以作为一个http客户端，去访问并下载http服务端上的固件（同时还可以由http服务器去管理设备固件），我希望的固件更新流程大体如下：
    1. 设备在正常情况下，4G模块处于MQTT模式，用于与MQTT服务器进行通讯，接收远程指令并执行。若此时需要更新设备固件，我先通过MQTT协议通知设备需要进行固件更新了，该MQTT消息还会包含一个http服务器的固件URL。
    2. 设备接收到该MQTT消息后，会记录该http服务器的固件URL，并将4G模块切换到http模式并保存重启（该4G模块需要保存重启后新的配置才能生效）
    3. 随后4G模块可以通过http协议从http服务器的固件URL下载该固件并有设备写入slot1中
    4. 固件下载完成后，需要将4G模块重新切换到MQTT模式并保存重启
    5. 最后再由工程师通过MQTT通知设备进行固件测试，测试完成后再通过MQTT通知设备进行固件确认
5. 为测试4G模块的通信质量，需要增加一个心跳超时次数，平均时间，最大时间，最近一次超时时间戳的统计，由此来反应4G模块的通信质量，该数据可以通过离线日志（每次心跳超时就记录一下）和mqtt命令查看
